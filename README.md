# Passive

Passive is a native C++20 ImGui overlay for Minecraft 1.21.11 (Fabric). It is designed for single-player use and attaches to Minecraft's OpenGL render loop through MinHook. Module data is read through the Java JNI bridge; ESP draws locally and does not send custom packets.

## Interface

- Press **RSHIFT** to open or close the menu; **Ctrl+Shift+End** requests an unload (Settings > General > SELF DESTRUCT does the same, in two steps).
- A brand band runs along the top of the panel, with a command bar of category chips under it: Combat, Mace, Misc, Movement, Spear, Visual, Crystal and Macros, each chip carrying its module count. Content spans the full panel below the bar. Each category has a live module search field.
- Every module carries a **safety tag**, drawn as a chip beside its name: a tick for **Safe**, a warning triangle for **Experimental**, **Unsafe** and **Blatant**, coloured green, yellow, red and red-pink. Hovering the chip explains what the tag means. The chip is shown in the Default, Squared and Dropdown layouts.
- Settings contains General, Appearance, Controls, Friends, Configurations, and About. General holds **Change Interface**, a dropdown that switches the whole menu between the **Default** layout (command-bar chips, one category per page) and the **Dropdown** layout.
- Dropdown interface: a second, complete interface rather than a reskin of the Default one. There is no command bar — a draggable strip of category **tabs** fills the same band, each with its category's icon, name and module count, the selected tab filled and underlined. Drag one tab onto another to reorder them and the order is saved. The selected tab lists its modules as flat rows: the name, the safety chip and a custom **toggle button** carrying ON / OFF (or MACRO) written inside it, which eases between the two states and is the only thing that switches the module — the row body beside it opens the module's own settings view, so reaching for the settings can never flip a module. That settings view carries a BACK button, the module's category icon, name and safety chip, a short description of what the module does and then its own card with every setting, drawn by the same renderer the Default interface uses, so a setting behaves identically in both. A live search reaches every category at once. Its cards, sliders and toggles keep their own flat, square look, and Module Style / Module Shape (which belong to the Default interface) are hidden while it is selected. Both interfaces read and write the same module state and saved configuration, so switching between them never resets anything.
- Appearance provides individual color wheels for the background, sidebar, cards, borders, text, and accent, plus a **Module Appearance** section holding the module **Style** (Default / Rounded / Squared / Minimal / Outline) and **Module Shape** (Rectangle / Squared), and **Reset to Default**.
- Every slider in the interface is the same widget: a filled value bar that animates toward the value, with a readout you can click to type an exact number.
- Module Shape **Squared** lays every module out as a square card in a three-wide grid. Each card keeps its description, and an open configuration becomes its own square panel attached under the card, animated, scrolling inside when the options are taller, and drawn over the cards below it.
- Binding a module: click its keybind and press a key. **Escape while capturing sets the bind to None**, so an accidental Escape can always unbind a module again, and no module or macro keybind fires while a game screen — chat included — is open, so a letter typed into chat never toggles the module bound to it.
- General > Interface holds **Debug Mode** (modules report what they are doing) and **Notifications** (friend joins and the module you just toggled). Debug toasts carry a green DEBUG MODE chip; without Debug Mode the modules stay silent.
- Friends (Settings > Friends) marks players by username (typed or picked from the players currently in the world). Entity modules (AutoMace, Triggerbot, Triggerbot V2, Auto Shield Break, AimAssist, Ghost Hand) skip friends, and AutoWeb never head-webs one, and ESP can draw them in their own color.
- The crosshair stays visible inside the inventory, the Escape menu and the other game screens: the game hides its own as soon as a screen opens, so Passive draws one while a screen is up.
- Combat: Triggerbot, AutoMace, Auto Shield Break, Auto Jump Reset, AimAssist, Pearl Agro, Stun Web. Mace: AutoMace, Breach Swap, Pearl Catch, Auto Windcharge, Auto Mace V2. Crystal: AutoAnchor, Auto Totem. Macros: Lunge Macro, Cobweb Macro, Xbow Macro, Instant Cart Macro. Spear: Auto Spear, Instant Spear Kill. Misc: Auto Drain, Auto Pressure Plate Web, Cart Refill, Auto Pot, Anti-Bot, Ghost Hand, Drag Click Friend, AutoClean, Item Scroll, Lag Reach. Visual: HUD, Arraylist, ESP, Shader ESP, Motion Blur, Walk Trail, Logout Spots, Nametags, StaticFov, Trajectory Preview, Player Model, Wings, Headwear, Capes, ViewModel. Every module card has an expand arrow for its options. See CHANGES.md for the latest fixes.
- **AutoMace** (Combat) swaps to the mace for a falling smash: it trades an elytra for a carried chestplate, selects the mace, swings on a random tick delay and puts the elytra back. **StunSlam** opens the same sequence with the hotbar axe so a raised shield comes down first, with **Axe ticks**, **Mace ticks** and **Swap ticks** pacing the three steps, plus **Swap Back**, **Elytra Swap**, range and the hit / cooldown / reswap tick windows.
- **Triggerbot** (Combat) swings at the entity under the crosshair on a random delay. Swords and axes each have their own Minimum / Maximum window; **All Items** paces any held item with the sword window. **Work In Screen** and **On Left Click** gate when it may fire, **While Use** and **While Ascending** keep it off while eating or rising, **Check Shield** leaves a target whose raised shield faces you alone, **Only Crit Sword / Axe** wait for a critical hit, **All Entities** and **Stray Bypass** widen the target test, **Same Player** stays on the last target, **Swing Hand** plays the arm swing, **Use Shield** raises the off-hand shield between swings for Shield hold ms, and **Click Simulation** posts a real left click to the game window instead of attacking through the interaction manager.
- The **Spear** page holds **Auto Spear** and **Instant Spear Kill**. Auto Spear right-clicks the held spear on a cadence at a valid target in front of it (Allow players / Allow entities, Range, Use delay, Only when looking, Silent Aim, No Glide). Instant Spear Kill writes a large client-side velocity to the player as the spear is used, because the spear's damage scales with your speed; Silent restores the real velocity the same frame so the movement the server is told about is left alone (Simulated Speed, Hold Ticks, Add downward velocity, Require target).
- Triggerbot's **Criticals** dropdown picks how it treats critical hits: **Default** never stalls, **Prio Crit** holds a swing while a crit is on offer and falls back to a plain hit after **Prio Crit wait**, and **Only Crit** only swings when the hit would crit. A crit is read as airborne + falling, so a knockback counts without a jump.
- **Triggerbot V2** is the second Combat card beside Triggerbot, with the same switches (Allow entities, Allow players, Require full attack charge, Require weapon, Criticals, Prio Crit wait, Attack delay) plus **OnHit Allowance**: a swing from this card counts as the left click Auto Shield Break's **OnHit** mode is waiting for, so the shield break goes out on the triggerbot's own attack instead of needing a physical click on top of it. Its swing is the game's own left click rather than a call into the game, so the game applies its own attack, hand state and swing animation, and every switch above still gates that click. The two triggerbots have their own settings and their own pacing, and each still only sends one swing per frame. **Auto Shield** (Combat, experimental) hangs off this card only: a V2 swing raises the off-hand shield through the game's own **Use Item / Place Block** key (Shield Delay 0-600 ms) and lowers it again after a hold drawn between **Shield Minimum Hold Time** and **Shield Maximum Hold Time** (0-1000 ms), with **Require weapon** on by default.
- **Instant Cart Macro** (Macros) fires a partially charged bow, then places a rail and a TNT minecart. The bind starts the bow straight away - no block has to be under the crosshair to begin - and the rail placement is the only step that needs one, inside block reach of you, when it happens. Both placements hold the game's own **Use Item / Place Block** key, so the game's tick does the placing (Bow Draw Time, Rail Delay, Cart Delay, Swap Back).
- **Auto Windcharge** (Mace) is a toggle, not a bind: every ender pearl that appears at you is followed as a live entity and the wind charge's own flight is solved against that pearl's per-tick positions, so the charge goes out on the first tick its travel reaches the pearl — the boost that carries the pearl, and the player who teleports to it, onto the high ground. Nothing is timed by a fixed delay, so a sprinting or gliding throw (both projectiles inherit your velocity) is met on the arc it really flies. **Max Catch Ticks** (1-100) ignores pearls older than that, **Max Meet Ticks** (1-160) refuses an interception that cannot happen soon enough, **Ping Offset** (0-600 ms) moves the meeting point down the pearl's flight to cover throw latency, and Silent Aim keeps the camera where it was. The solver lives in `agent/modules/wind_charge.h` and is exercised by `test/build-wind-charge.bat`.
- **Auto Mace V2** is a different engine from AutoMace: a scan scores every living target in **Attack Range** by how far it is falling, how close it is and how near your view it sits (the crosshair is never the gate, so a target in reach a few degrees off is still found), then a small timed plan aims, equips and swings, and is consumed once. **Auto Aim** turns onto the target's hitbox before every swing, and the swing is `MinecraftClient.doAttack()` — the call the Attack And Destroy key makes — so it only goes out when the game's own crosshair pick is that target and the attack cooldown is full. **AutoMace Retry** is the wait between smashes and **StunSlam Cooldown** the wait after a stun slam; one smash per fall, and a held attack never re-arms it. StunSlam still goes axe (shield down) then mace, with Custom or MMC timings.
- Lag Reach extends the crosshair attack reach: a fresh press of your own left button is one reach, the look ray is tested against every player's hitbox, and every reach rolls a fresh distance between 3 blocks and Max Reach (3–6). It never attacks by itself and never autoclicks - a held button is not a held reach - and the line to the hitbox has to be clear of solid blocks, so the extended reach cannot hit a player through a wall. The server still decides which hits it accepts.
- Walk Trail draws a grey line along the ground you have walked over and fades it out behind you (Trail Colour, Trail Length, Trail Width, Max Points, Fade, Animated Pulse, Through Walls). With Through Walls off, each point's visibility is decided when it is recorded, because the overlay has no depth buffer of its own.
- **Motion Blur** (Visual, safe) smears the last couple of frames behind the current one along the direction the camera turned, so a fast turn streaks and standing still draws nothing (Motion Blur Strength, Motion Blur Speed, Turn Sensitivity). It is one GPU blit and at most two quads through the render module's history ring, so it takes nothing off the frame rate.
- Visual also carries the five Clarity cosmetics: Player Model, Wings, Headwear, Capes and ViewModel. They are drawn by the client itself — no external jar, and the game's own models are never touched. Player Model draws a blocky body at the chosen scale; Wings draws two animated feathered quads per style; Headwear draws a crown, halo, horns or orbiting orbs above the head; Capes draws a cloth quad with physics and movement waves; ViewModel draws the first-person item from its own texture with the card's position, rotation, scale and opacity (Off Hand draws the other hand, and an untouched card draws nothing). If `clarity-1.2.0.jar` is present it is still loaded and driven, but nothing depends on it.
- Stun Web is an add-on to Auto Shield Break: after the axe stun lands, a second click goes out and a cobweb is placed under the target (Web Look: Instant / Smooth, with **Camera Sensitivity** and **Silent Place** under Smooth; Smooth is on the block in a fraction of a second, so the web follows the aim instead of pausing first). **Look Back** walks the view back to the direction it held before the stun once the web is down, and the whole sequence stands down while a cobweb is already around the target (or around you). It needs a cobweb in the hotbar and block reach. **AutoWeb** (also Combat) is the experiment beside it: the card carries that whole shield-stun follow-up in its own **Stun Web** section, and adds **Allow Head Web**, which drops a cobweb on the block a player you just hit is standing against and one in the cell above it (their own cell and their head), so a hit while they are pinned to a wall webs them in place — it needs the same hotbar cobweb and block reach, and stands down while a stun-web attempt is mid-flight. Logout Spots draws a box (Logout color, black by default) where a player stood when they left the world. The Xbow Macro card has a **Fire placement type** dropdown (Instant / Smooth) with the same **Camera Sensitivity** and **Silent Place** options for the fire step, and Auto Totem has a **Type** dropdown (Vanilla / Crystal, or SMP with a health threshold, shield slot and swap delay).
- Ghost Hand only helps a click of your own that lands on a cobweb (the player or mob inside it takes the hit); it never swings by itself, and one press is one assist - the button has to come back up first. **AutoMace** performs a single mace per fall and, with **Only On Your Own Click** on (the default), that smash is your click and never the module's, armed once per press; **Stun Slam speed** is the wait between the axe stun and the mace, and **Anti Spear Stun Slam** keeps a held spear to spear → axe → mace without putting the spear back in between. **Breach Swap** answers a fresh press of your own left click — one press, one swap — and the crit is read as airborne + falling, the same signal Triggerbot's Criticals uses. **Auto Drain**'s **Web Draining** arms on the **top face** of any block whose cell above holds a water source (the shape you leave when you place a block and pour water onto it) or on water that sits on a block, so the cobweb drops into the water's own cell; any other face is refused, and **Silent Place** places it against a rotation your camera never takes. **Auto Pot** repots the missing buffs (Speed is the Swiftness potion), honours **Inventory Delay** down to a few milliseconds, and has a **Look Down** dropdown (Instant / Smooth) with Camera Sensitivity, Silent Aim, **Look Back** and a health potion threshold. Drag Click Friend ramps the click rate from Minimum to Maximum CPS while attack is held, with an optional pause. Shader ESP switches on Minecraft's own glowing outline around players and dropped items (the "outside their skin" glow, white, around the rendered model including armour, held items and dropped item models), with the item in your own first-person hand drawn from its texture; its Custom style keeps the drawn halo with its own colour, friend colour, thickness and opacity.
- Visual contains Arraylist, ESP and Shader ESP. ESP supports 2D boxes with a health bar, and 3D hitbox boxes with fill or outline plus a health indicator, separate player/entity filters, a color picker and a friend color. Shader ESP outlines players and dropped items with Minecraft's own glowing effect, and the item in your hand with a glow drawn from its texture (Hand Glow Size / Nudge X / Nudge Y / Rotation). Its Custom style is the drawn glow: a halo of thickness passes under a solid rim, at the chosen opacity, in the player and friend colours.
- **HUD** (Visual) draws Passive's own HUD: a rounded, animated hotbar (fade-in, a pop on the newly selected slot, slot numbers and stack counts) with item icons, separated rounded panels carrying the health/armour bars on the left and the food/XP bars on the right (each with a vector heart / shield / drumstick / orb glyph and its values), a held-item name plaque with the item's icon that appears when the held stack changes (an item with no custom name is named from its own translation key, so a golden apple reads "Golden Apple" rather than the text component's internals), an attack speed bar under the crosshair that fills as the swing charges, and a custom crosshair chosen from presets (Cross, Dot, Cross + Dot, Circle, Circle + Dot, T-Shape, Chevron, Arrows) or painted on a 9x9 **Draw Board**. Its card carries the element switches (Custom hotbar, Hotbar animations, Rounded hotbar, Slot numbers, Item counts, Held item plaque, Bar panels, Attack speed bar, Custom crosshair, Cover vanilla hotbar/bars), the hotbar scale / rounding / animation speed and colours, the panel scale, offset, icons, values and colours, the plaque scale, hold time and icons, the attack bar scale and colour, and the crosshair preset, size, gap, thickness, dot, rotation, outline, dynamic opening and colour. **Cover vanilla hotbar/bars** draws an opaque plate over the game's own hotbar and bar rows (Plate opacity, 100% by default, so nothing of the vanilla bar shows through the drawn HUD), placed at the game's own GUI scale — falling back to a scale estimated from the framebuffer height when that cannot be resolved — so the game's HUD never has to be switched off: the first-person hand, the chat, the Tab list and the scoreboard stay exactly as the game draws them. The card also carries the bar behaviour (**Bars slide to the new value** with its animation speed, **Heart beats below 2 hearts**, **Absorption: yellow health bar**) and the **Crosshair indicator** (off by default, with its Range and Indicator colour). While absorption is held the health row is yellow and its maximum is the health plus the absorption held right now; below two hearts the heart glyph beats, faster the lower the health is. The crosshair indicator draws the crosshair in its own colour, a little larger than the game's own, while the crosshair ray is on a living entity inside the range.
- Nametags draws real item and armor icons (loaded from the game's own asset namespace), armor trim overlays, an enchantment glint, Minecraft-style durability bars (read from the stack's damage and max damage, with the component text as a fallback), the held item with its stack count, health and distance, all scaled with distance. **Single Show** draws a board only for the player or entity the crosshair is actually on, instead of every player in view.
- Presets save enabled modules, their options, the friends list, interface behavior, and theme colors. They are stored in `%APPDATA%\Passive\configs`; Export copies JSON to its `exports` folder.

## Injection notes

The injector resolves fonts and the agent DLL relative to its own executable, so it can be launched from Prism or another working directory. It uses a synchronized status view and confirms startup after the overlay's ImGui render context is ready. A failed startup message points to `passive_agent.log` beside `javaw.exe` or in `%TEMP%`.

The injector is **v1.0.2**: a graphite window with platinum accents and rounded DWM corners, status cards for the agent DLL, the detected process and the startup handshake, and an animated tab bar. **Inject** is the one-button flow that finds the first Minecraft process. **Multi Instance Injecting** lists every running `javaw.exe` / `java.exe` with its window title and whether Passive is already loaded, and injects into the instance you select — useful when more than one client is open at once. The `--pid` command line path is unchanged.

## Fabric jar

`fabric\build-jar.bat` packs the same client into a normal Fabric mod jar,
`fabric\dist\passive-fabric-1.0.2.jar`. Drop it into the instance's `mods\` folder and Passive is there when the
game starts: no injector and no DLL to copy beside the launcher, and no other mod or Fabric API needed.

It carries the built `passive_agent.dll` (the ImGui menu and every module, unchanged) and the Inter faces the
interface draws with. At startup the loader unpacks them into `<gameDir>\config\passive\native\` and maps the
client into the game process. Only `passive_bridge.dll` is loaded with `System.load`; the bridge maps the
client itself and owns the single load reference. When the client finishes its teardown it reports
`passiveUnloadComplete`; the bridge then frees that reference, so **Ctrl+Shift+End** (or Settings > General >
SELF DESTRUCT) really takes the DLL out of the process and `passive_injector.exe` can inject that same DLL
again afterwards. The log is the usual `passive_agent.log`, beside the runtime's `javaw.exe` or in `%TEMP%`.
See `fabric/README.md` for the details.

## Build

Requirements: Windows 10/11, Visual Studio 2022 Build Tools with the C++ workload, and CMake 3.20 or newer. Run `build.bat` from this folder. It builds:

```text
build\Release\passive_agent.dll
build\Release\passive_injector.exe
build\Release\passive_bridge.dll
build\Release\assets\fonts\Inter-*.ttf
```

`fabric\build-jar.bat` builds the Fabric mod jar on top of that (it runs the native build first) and needs a
JDK 21:

```text
fabric\dist\passive-fabric-1.0.2.jar
```

## Source layout

```text
agent/core/     DLL bootstrap, published entry points, and render/input hooks
agent/config/   preset file management
agent/gui/      interface, theme, and animation helpers
agent/jni/      Java VM bridge, Minecraft 1.21.11 wrappers, and the Clarity cosmetic jar loader
agent/modules/  module registry, settings, and every module's logic
agent/render/   OpenGL state and render utilities
injector/       standalone Windows injector
fabric/         Fabric mod jar: loader, bridge source, and its build script
assets/fonts/   bundled Inter font faces
```
